## START HERE: the Portuguese language bug (Sonali found this by hand, 2026-08-01)

**Her report, verbatim:** "i clicked middle school and got put to elementary
school. i saw some english things. when i pressed the back button everything
turned english."

**None of the automated suites caught any of it.** They pass. Trust her, not them.

### Her hypothesis, which is probably correct
> "why isnt there a different set of links entirely for portuguese. maybe that
> would solve things?"

**Language currently lives only in `localStorage.pai_lang`**, read per-page on
mount. Nothing about the URL says Portuguese. So any page that mounts before the
value is read, is served from cache, or is reached via browser back/forward can
render English. That fully explains "back button → everything turned English."

**The structural fix she is pointing at: put the language in the URL** —
`/pt/lesson/131`, or a route group, or a `?lang=pt` param carried everywhere.
Then language survives navigation, back/forward, refresh, caching and sharing.
This is very likely the right fix and should be scoped before more patching.

## Why the tests missed it (do not repeat this)

The suites check **routes, data and layout**. They set `pai_lang` directly in
localStorage before loading, so they never exercise **choosing** a language,
never navigate with the **back button**, and never cross the elementary/middle
seam. They test the app in a state a real student never reaches.

**Three false-pass traps hit this session — all three cost hours:**
1. A run reported 56/56 clean; every request had failed at TLS and never
   reached the server.
2. A pressure test reported no jailbreaks; the route never sent the student's
   question to the model, so it graded 56 empty prompts.
3. Three browser agents shared one browser and overwrote each other's logins,
   producing two contaminated reports with false "blockers".

**Rule: a check you have not seen FAIL against known-broken input is not a
check.** Verify each new test against a deliberately broken snapshot.
